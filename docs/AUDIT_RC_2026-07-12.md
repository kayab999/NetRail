## 1. Executive summary

NetRail is a **credible Linux research console**: Rust-primary Axum API, Tauri 2 shell, multi-backend fanout, typed errors, encrypted local history, and a deliberately narrow localhost threat model. Functionally, the 1.2.x line (Wikipedia fallback, DDGS bot-challenge detection, recovery UX, packaged static UI) is **product-complete for an RC**.

It is **not RC-ready for promotion** until process and quality gates are green:

| Gate | Status | Evidence |
|------|--------|----------|
| Unit / integration tests | ✅ Pass | Rust **48** tests · Python **35** tests |
| Clippy on `main` | ❌ Fail | `TrayState` dead-code under `-D warnings` |
| GitHub CI (`main`) | ❌ Red | 3 consecutive CI failures on latest commits |
| Release workflow on tag | ✅ Green | v1.2.1 Release job succeeded |
| User-facing GitHub Release | ❌ Draft only | v1.2.0 / v1.2.1 not published; **latest = v1.1.1** |
| Version single source of truth | ❌ Drift | Python `__version__`, README, MANUAL still 1.2.0 |
| CHANGELOG completeness | ❌ Gap | No `## [1.2.1]` section |
| Dual-stack parity (Rust ↔ Python) | ⚠️ Partial | API routes match; Wikipedia + `search_recovery` Rust-only |
| Security model | ✅ Acceptable for localhost v1 | Residual risks documented |

**Verdict:** Treat **v1.2.1 as pre-RC**. Ship **RC-1 as v1.2.2** (or re-tag after a small hygiene patch) once P0 gates below are closed. Do not publish draft 1.2.1 as “latest” without fixing CI and version alignment first.

## 2. Scope & method

### In scope

- Rust engine (`src-tauri/`) — search fanout, security, history, server, desktop
- Static UI (`netrail/static/`)
- Python fallback (`netrail/`) — Docker / Flatpak / `install.sh`

### Out of scope

- Non-Linux platforms

### Method

1. Architecture review against `docs/ARCHITECTURE.md` and live code
2. Security review of URL validation, CSP, encryption, bind address
3. Parity diff Rust vs Python routes and search behavior
4. Local verification: `cargo test`, `cargo clippy -D warnings`, `pytest`
5. Remote verification: GitHub Actions outcomes, release draft assets
6. Prior audits (`AUDIT_TECHNICAL_*`, Tribunal v12, UI/UX) checked for residual debt

## 3. Architecture assessment

### 3.1 Production topology (sound)

```
Tauri 2  ──webview──►  http://127.0.0.1:7421
                              │
                     Axum Router (build_router)
                              │
              ┌───────────────┼───────────────┐
              ▼               ▼               ▼
         static UI      fanout backends    history SQLite
         app.js/CSS     ddgs│searxng│brave │ + Wikipedia fallback
                            merge+dedupe     Fernet / keyring
```

**Strengths**

- Single-process native path; no Python sidecar for desktop
- Shared `reqwest::Client` pooling
- Injectable `settings_fn` for HTTP integration tests
- Headless `netrail-api` binary for scripting/homelab
- Route surface identical between Rust and Python (14 API paths)

**Structural risks**

| Risk | Severity | Notes |
|------|----------|-------|
| Dual implementation (Rust + Python) | Medium | Feature drift already visible (Wikipedia) |
| Monolithic `server/mod.rs` (~540 LOC) | Low | Maintainability, not correctness |
| Large `history/mod.rs` (~760 LOC) | Low | Schema + store + tests co-located |
| DDGS HTML scrape fragility | High (ops) | Known; mitigated by Wikipedia + recovery UX |

### 3.2 Search path maturity (1.2.x)

Post–Tribunal v12, empty DDGS is no longer silent:

1. Detect bot-challenge HTML → `DDGS_BOT_CHALLENGE`
2. Empty batches → `errors[]` + `tracing::warn!`
3. Total empty web fanout → Wikipedia OpenSearch + extracts
4. UI: short error banner, dismiss, recovery hints
5. `/api/health` → `search_recovery` hints

This is the correct reliability posture for a metasearch product.

## 4. Security assessment

### 4.1 Controls (effective for stated model)

| Control | Implementation | Assessment |
|---------|----------------|------------|
| Bind address | `127.0.0.1:7421` only | ✅ |
| No telemetry | Explicit health field + policy | ✅ |
| Open-URL SSRF / XSS schemes | `security.rs` / `security.py` | ✅ localhost, rebinding, credentials, schemes |
| Backend URL hardening | Metadata + rebinding blocked; localhost allowed | ✅ intentional |
| CSP | Axum middleware + Tauri CSP | ✅ `unsafe-inline` styles only |
| History encryption | Fernet + keyring / `NETRAIL_DB_KEY` | ✅ with documented degrade |
| Frontend result rendering | `escapeHtml` for titles/URLs/snippets | ✅ |
| Tauri capabilities | Minimal (window/tray/shortcut) | ✅ |

### 4.2 Residual risks (accept or track)

| ID | Risk | Severity | Recommendation |
|----|------|----------|----------------|
| SEC-01 | **No API auth** on localhost — any local process can search/read history | Accepted (v1) | Document in RC notes; optional token in v1.3+ |
| SEC-02 | **Open URL allows RFC1918** (e.g. `http://192.168.1.1`) | Low–Med | Document; optional strict mode for corporate |
| SEC-03 | Encryption degrade → plaintext session when keyring missing | Med | Already bannered; keep as RC acceptance criterion |
| SEC-04 | FTS5 index holds **plaintext tokens** of queries | Accepted | Honest README threat model |
| SEC-05 | Image results load remote `https:` images (privacy) | Low | By design for Images mode |
| SEC-06 | Markdown docs via `innerHTML` | Low | Local trusted content only |
| SEC-07 | `SECURITY.md` supports only **1.0.x** | Process | Update to 1.2.x before RC |

No remote RCE / LAN exposure path found in default config. **No P0 security blockers** for localhost RC.

## 5. Quality gates (empirical)

### 5.1 Tests (2026-07-12 local)

```
cargo test          → 48 passed (40 lib + 8 api_error_codes)
pytest tests/       → 35 passed
cargo clippy -D warnings → FAIL
  desktop.rs: field `0` of TrayState never read (dead_code)
```

### 5.2 CI / Release

| Pipeline | Branch/Tag | Result |
|----------|------------|--------|
| CI | `main` (v1.2.1 commit) | **failure** |
| CI | prior 1.2.x commits | **failure** |
| Release | tag `v1.2.1` | **success** (artifacts present) |

**Root cause of CI red:** Clippy treats unused `TrayState(0)` field as hard error. The field is intentionally kept alive via `app.manage(TrayState(tray))` so the tray icon is not dropped on Linux. Fix: `#[allow(dead_code)]` with comment, or `_` prefix / `#[allow]` on the tuple field.

**Note:** Release workflow runs `cargo test` but **not** clippy — so green Release + red CI is expected and dangerous for process credibility.

### 5.3 Frontend

- Splash TDZ (`RESULTS_PAGE_SIZE`) fixed in tree
- Result cards, pagination, fanout error UX polished for 1.2.1
- No automated UI/E2E (gap for post-RC)

## 9. Workplan to RC (professional execution plan)

### Target definition

| Item | Definition |
|------|------------|
| **RC artifact** | `NetRail_1.2.2_amd64.AppImage` + `.deb` + `netrail-api` + `SHA256SUMS` |
| **RC channel** | GitHub Release marked **pre-release** `v1.2.2-rc.1` **or** published `v1.2.2` with “RC” in notes |
| **Support surface** | Linux amd64 desktop (AppImage/deb) + headless API |
| **Known limitations** | DDGS may captcha; Wikipedia fallback; Python lag unless P1-3 done |

### Phase A — Hardening (exit: CI green)

**Duration:** 0.5 day  
**Exit criteria:** `main` CI green; clippy + tests green locally and on GitHub.

| Task | Acceptance |
|------|------------|
| A1 Fix `TrayState` dead_code for clippy | `cargo clippy --all-targets -- -D warnings` exit 0 |
| A2 Bump Python `__version__` to match | `/api/health` version consistent on both stacks |
| A3 Sync README + MANUAL install filenames | Grep shows single version |
| A4 CHANGELOG `[1.2.1]` + prepare `[1.2.2]` | Semver history complete |
| A5 Update SECURITY supported versions | 1.2.x Yes |
| A6 Optional: add clippy to `release.yml` | Release cannot greenwash red lint |

### Phase B — Parity & product polish (exit: RC feature freeze)

**Duration:** 0.5–1 day  
**Exit criteria:** No open P0; P1 either done or explicitly waived with written rationale in release notes.

| Task | Acceptance |
|------|------------|
| B1 Wikipedia fallback in Python **or** Docker doc waiver | Written decision |
| B2 `search_recovery` on Python health if B1 implemented | Schema match |
| B3 Manual QA checklist (below) on local release build | Sign-off |
| B4 Discard/publish old draft 1.2.0 | One latest path |

### Phase C — RC build & publish (exit: installable RC)

**Duration:** 0.5 day

| Task | Acceptance |
|------|------------|
| C1 Tag `v1.2.2` (or `v1.2.2-rc.1`) from green `main` | Tag points to CI-green commit |
| C2 Release workflow green; SHA256SUMS present | Artifacts downloadable |

| C4 Search smoke: query with DDGS captcha path still shows Wikipedia or recovery | No silent empty rail |
| C5 Open published release (or mark pre-release RC) | Users can download from GitHub |
| C6 Point README “latest” links at RC/GA | Docs match reality |

### Phase D — RC soak → GA (exit: v1.2.2 stable)

**Duration:** 3–7 days soak (or accelerated if solo maintainer)

| Task | Acceptance |
|------|------------|
| D1 Collect issues (DDGS, packaging, tray) | Issue triage |
| D2 No P0/P1 regressions | Patch RC if needed |
| D3 Promote to non-prerelease / finalize notes | GA |

### Manual QA checklist (RC sign-off)

Copy into the release PR or issue:

- [ ] `curl -sf http://127.0.0.1:7421/api/health` → `status=ok`, correct `version`
- [ ] `GET /` returns full HTML (search form present)
- [ ] `GET /static/app.js` → 200
- [ ] Web search returns results **or** Wikipedia + non-empty `errors[]`
- [ ] Images mode does not crash
- [ ] Open result launches browser; `http://127.0.0.1` open rejected (`OPEN_URL_LOCALHOST`)
- [ ] History list / purge with encryption banner behavior sane
- [ ] Keyboard: ↑/↓ Enter; Help docs open
- [ ] Tray: Show / Quit works on Linux
- [ ] AppImage: `APPIMAGE_EXTRACT_AND_RUN=1` path documented and works without FUSE
- [ ] `netrail-api --api-only` serves health without GTK
- [ ] SHA256SUMS match downloaded files

## 11. Recommendation (decision record)

1. **Do not** promote draft **v1.2.1** as “latest” until Phase A is complete.  
2. Prefer **v1.2.2** as the RC/GA vehicle: includes clippy + doc fixes as a clean patch.  
3. Keep product scope frozen: no Phase 6 crawler/AI work inside the RC window.  
4. After GA, schedule P2 dual-stack strategy: either invest in Python parity tests or formally freeze Python features and point Docker at `netrail-api`.

**Overall readiness score (pre-Phase A):** **6.5 / 10** — strong product core, weak release process gates.  
**Projected readiness after Phase A–C:** **8.5–9 / 10** for Linux desktop RC.
